# AoE2 模组管理器 · v0.3 定稿总结

> 版本定位：从「只读原型」正式变成**可安全安装 / 启用 / 卸载**的实用工具。
> 技术栈：Tauri 2 + Vue 3 + TypeScript + Vite + Rust（Windows 10 / GNU 工具链）。
> 项目路径：`F:\AoE2ModManager`，游戏模组根目录：`F:\Games\AoE2DE`。

---

## 一、本版最重要的发现：游戏客户端替我们完成了"真订阅"

**现象**：把模组装到 `<root>\local\{WorkshopID}_{标题}\`，并在 `mod-status.json` 里登记
`Path = "local//{WorkshopID}_{标题}"`、`Enabled = true` 之后——

1. 游戏**直接识别并加载**了该模组（无需任何额外操作）；
2. 启动一次游戏、再刷新官网 `/mods/subscribed`，该模组**变成了"已订阅"状态**。

**对照实验（同一版本的多次尝试）**：

| 尝试 | 结果 |
| --- | --- |
| Rust `ureq` 直接 `GET /api/v4/mods/Subscribe/{id}`（带 Cookie/Origin/Referer） | HTTP 200，但服务器**不记账**，官网始终显示未订阅 |
| WebView2 页面内 `fetch(..., {credentials:'include'})` + `POST /Installed` 反查 `verified=true` | 仍然可能是"假成功"，官网状态不变 |
| 装到 `local/` 并写好 `local//` 记录 → 启动一次游戏 | **官网真的变成已订阅** |

**机制推断**（与游戏自己的行为一致）：客户端启动时会读取 `mod-status.json`，
对 `Path` 以 `local//` 开头、且文件夹名带 `{WorkshopID}_` 前缀的条目，视为"用户拥有的官方模组"，
用客户端自身凭据与服务端订阅集合**求差并同步**，于是订阅被真正建立。

**架构结论**：

> 我们只负责把**文件与记录摆成游戏认可的形态**，一切鉴权级写操作交给游戏客户端。
> 这既绕开了官方 Web 接口的风控/假 200，又天然符合底层同步逻辑——
> 比"伪装调用 Subscribe"既安全又可靠。

因此 v0.3 的最终策略是：**放弃直接调用 Subscribe，全部走 local 兜底**，
并把这条链路做成"一次落盘"的原子管线（见第三节）。

## 二、已交付能力（v0.3 全量）

| 能力 | 说明 | 主要实现 |
| --- | --- | --- |
| 本地扫描 | 真实读取 `local` / `subscribed`，`info.json` 容错解析（含裸 CRLF）、缩略图、官方 Tag 分类 | `scan.rs` |
| 在线浏览 | 官方 API（登录态 WebView2 + DPAPI 缓存 Cookie）、分类/排序/无限滚动、详情、跳转官网 | `online/*`、`OnlineBrowser.vue` |
| 下载安装 | 签名下载 → 解压校验（防路径穿越/可执行文件）→ 原子改名安装 → **补 `info.json`/缩略图** → **移入 `local`** → 一次写 `mod-status.json` | `download.rs`、`install.rs`、`lib.rs::online_install` |
| 启用 / 禁用 | 单条切换，写前查进程 → 备份 → 只改 `Enabled` → 原子替换 → 回读校验 | `presets::set_enabled`、`ModDetail.vue` |
| 卸载 | 取消订阅（WebView2 内退订，尽力而为）+ 删除本地目录（严格校验：单段名 / 真实目录 / 拒 junction / 规范化父目录）+ 清记录 + 清分类元数据 | `install::resolve_uninstall_target`、`presets::remove_record` |
| 预设与批量恢复 | 预设存软件配置目录；恢复时只把匹配记录的 `Enabled` 改成 `true` | `presets.rs`、`PresetManager.vue` |
| 界面 | 羊皮纸 + 金框卡片式三栏布局，分类/来源/状态筛选，Toast 局部反馈（不重载列表） | `App.vue`、`style.css` |

**信息补全（游戏识别模组的关键）**：
实测本机 175 个官方下载的模组，游戏自己写的 `info.json` **全部只有 4 个键**：

```json
{"Author":"…","CacheStatus":0,"Description":"…","Title":"…"}
```

（字母序、紧凑 JSON、UTF-8 无 BOM；没有 WorkshopID / Version 等字段。）
我们按同样结构补写；缩略图 `thumbnail.png` 改名 `thumbnail.jpg`，
缺失时用官方 API 的缩略图地址下载补存。

## 三、安全写入模型（三件套，所有写游戏文件的路径共用）

```
① 进程检查：tasklist 检测 AoE2DE_s.exe / AoE2DE.exe，运行中一律中止
② 备份：原始字节写入 %APPDATA%\com.aoe2.modmanager\backups\mod-status-<ms>.json（含大小校验）
③ 原子替换 + 回读校验：同目录临时文件 → rename 覆盖 → 回读解析并与内存值全等比对 → 不一致自动回滚
```

约束：
- **零侵入游戏目录**：不再写 `.aoe2mm-mod.json` 标记（旧标记只做识别与清理）。
- **最小改动**：只改 `Enabled` / `Path`，其余字段（`CheckSum`/`LastUpdate`/`Priority`/`PublishID`/未知字段）原样透传。
- `CheckSum` 无法计算官方哈希，统一写 `"0"`，由游戏启动后自行补齐。
- 安装管线 6 个阶段每步都有日志与出口；`mod-status.json` **只写一次**（写最终形态 `local//`），
  写失败会把目录挪回 `subscribed` 再重试 `subscribed//`，绝不留下"文件与记录不一致"的残局。

## 六、已知限制

1. 官方 `Subscribe` 接口不可用（两种方式都试过），订阅只能靠游戏客户端同步；**不启动游戏时官网不会显示已订阅**。
2. 写 `mod-status.json` 要求游戏未运行（会明确报错要求先关游戏）。
3. 卸载时服务器退订属"尽力而为"（WebView2 + `/Installed` 反查，反查上限 200 条）。
4. 模组描述以原始 HTML 存储，软件内展示做纯文本化（游戏内展示原样）。
5. `updateAvailable` 目前只反映服务器状态，尚未结合本地版本做真实更新判定。

## 七、v0.4 迭代建议

### P0 · 一致性与正确性

1. **收敛为唯一"落位"API**：把 安装 / 转本地 / 卸载 / 切换启用 四条路径统一到
   `place_mod(target: Local|Subscribed)`，避免以后再加路径时又出现"半写"分支。
2. **真实更新检测**：对比本地 `info.json`/目录时间与服务器 `lastUpdate`，给出"可更新"徽章 + 一键更新
   （复用 `.bak-<ms>` 备份，保证可回滚）。
3. **启动自愈**：清理 `.aoe2mm-staging` 与 `*.aoe2mm-*.tmp` 残留（断电/崩溃后的孤儿文件）。
4. **资源冲突检测**：同名资源（`widgetui/`、`gamedata/*.dat` 等）跨模组覆盖提示，并给 `Priority` 排序建议。

### P1 · 体验

5. 本地页支持"更新 / 重新安装"（从在线页直接跳转并带上下文）。
6. 备份管理 UI：浏览 / 恢复 / 清理 `.bak-*` 与 `mod-status` 备份。
7. 批量操作：多选启用/停用、安装队列。
8. 列表虚拟滚动（面对 500+ 模组）与缩略图懒加载上限。
9. 窗口状态记忆 / 托盘最小化。

### P2 · 工程与可维护性

10. 把 `online_install` 的管线抽成可注入依赖的 `pipeline::install()`（下载器 trait），做端到端单测。
11. 一键导出诊断包（日志 + 最近备份清单 + 环境信息）用于反馈。
12. 说明文档同步：README 仍是"阶段一只读原型"，需改成 v0.3 现状；顶栏副标题
    「v0.3 · 预设与批量恢复」→「v0.3 · 本地化安装与预设管理」。
13. 可选：`tauri-plugin-updater` 自动更新（需签名）；羊皮纸浅色主题与 i18n。
